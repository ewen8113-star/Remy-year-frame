# HarmonyOS UI 交互逻辑基线

## 通用状态模型

所有可交互控件默认按以下状态模型实现：

- `normal`：默认态
- `hover`：悬停态（桌面端/指针设备）
- `focus`：键盘焦点态（含可访问性焦点可视化）
- `pressed`：按压反馈态
- `disabled`：禁用态（不可触发事件）
- `error`：错误态（输入、选择、校验类组件）

## 输入与校验

- 输入框需区分：未输入、输入中、完成输入、校验失败、禁用。
- 错误文案在组件近邻位置显示，避免仅依赖颜色表达。
- Search / Input / Selector 组件在失焦后进行轻量校验，在提交时进行完整校验。

## 列表、菜单与弹层

- 菜单支持普通项、禁用项、子菜单项；子菜单展开方向需避免遮挡触发源。
- 列表项点击区覆盖整行，主操作与次操作视觉区分明确。
- 弹层（Dialog/Toast/Popup）出现与消失需具备一致过渡节奏，禁止突变闪烁。

## 标题栏与导航

- TitleBar 结构遵循：返回/导航区域 + 主标题区域 + 右侧操作区。
- 不同端形态（Phone / Foldable / Tablet / 2in1）保持信息架构一致，只调整密度与排布。

## 主题与可读性

- Light/Dark 两套主题必须同构，语义 Token 一一对应。
- 强调色、警示色、禁用色不得混用；文本对比度满足可读性要求。

## 实施要求（本项目）

- 在 `public/style.css` 中维护语义变量，如 `--color-primary`、`--color-error`、`--text-on-primary`。
- 在 `public/app.js` 中对组件状态使用显式 class 或 data-state 控制，不用隐式副作用。
- 新增交互必须附带最小验证清单：状态覆盖、键盘可达、错误反馈、深浅色一致性。
